# Расчёт стоимости

## Доставка, версия 66

- В пределах одного населённого пункта — 1200 ₸ до надбавки. Между населёнными пунктами — 1200 ₸ + 200 ₸ за километр сверх первых 3 км общего дорожного маршрута, включая остановки и дробную часть километра.
- Применяется один наибольший действующий коэффициент. Итог округляется вверх до 50 ₸ один раз. Стоимость покупок в доставку и базу комиссии не включается.
- Без места получения показывается предварительная цена от случайной машины на карте. Позиция машины фиксируется на время этого расчёта и сохраняется при изменении коэффициента, движении анимации и выборе «Любой магазин».
- Кнопка «Купить в любом магазине» и ручной ввод «магазин»/«любой магазин» без дома и координат означают, что магазин выбирает водитель. Цена считается от закреплённой позиции до адреса доставки; такой заказ можно оформить без конкретного магазина. В заказ сохраняются показанная сумма и указание «Любой магазин — выбирает водитель».
- Для посылки без адреса получения цена остаётся предварительной; до отправки необходимо указать адрес. Конкретный магазин с адресом либо точкой на карте рассчитывается по своему маршруту.
- Машины на карте смоделированы. Это обозначено в расчёте; выбранная точка не является назначением настоящего водителя. Если у точки машины не определяется населённый пункт, применяется тариф по километрам найденного дорожного маршрута. Если машина или дорожный маршрут недоступны, сумма не выдумывается.
- Эти изменения не требуют обновления Firebase Rules или Functions. Существующие ограничения на товары с возрастными ограничениями сохраняются.

## Такси, версия 60

Цена сохраняется из того же расчёта, который клиент видит перед отправкой. Повторная синхронизация формы не меняет готовую цену. При смене маршрута, дома, категории или коэффициента старый расчёт становится недействительным.

- Белоусовка: 800 ₸ до 2 км, далее 120 ₸/км; действующий коэффициент и округление вверх до 10 ₸.
- Известный межгород: утверждённый прайс имеет приоритет в обоих направлениях. Например, Белокаменка ↔ Белоусовка — 3500 ₸ за легковой автомобиль. Автоматический коэффициент спроса и расчёт километража эту цену не заменяют.
- Для маршрута с остановками складываются только реально заданные участки прайса. Неизвестный участок или маршрут между двумя внешними населёнными пунктами переводит весь расчёт на километраж; воображаемый заезд через Белоусовку не добавляется.
- Межгород без прайса: 230 ₸/км по дорогам, действующий коэффициент, округление вверх до 50 ₸.
- Надбавка категории автомобиля применяется один раз поверх базовой цены.
- Если городской маршрут временно недоступен, диапазон базового тарифа показывается до оформления и сохраняется без изменений. Если межгород без прайса рассчитать нельзя, отправка заблокирована и доступен звонок диспетчеру. Диспетчер согласует сумму и оформляет заказ через существующую форму с числовой ценой. Заявка с неизвестной стоимостью автоматически не создаётся.
- Комиссия берётся по индивидуальной ставке водителя (0–100%). Ставка фиксируется при принятии/назначении заказа и применяется один раз при завершении. Для диапазона база комиссии — верхняя граница. 0% комиссии допустимы; нулевая стоимость заказа недопустима.

## Публикация защиты Firebase

Обновление GitHub Pages публикует интерфейс. Новые проверки серверных правил требуют отдельной публикации в проект `taxiuspeh-76d55`. В авторизованном Google Cloud Shell из свежей копии основной ветки:

```bash
bash scripts/deploy-pricing-rules.sh
```

Скрипт публикует только Firestore Rules. Firebase Functions и существующие данные он не меняет. Старые заказы автоматически не переоцениваются, списанные комиссии не пересчитываются. Пока правила не опубликованы, старые версии клиента всё ещё могут записывать нулевую стоимость; обновлённые кабинеты блокируют её принятие и завершение.

## Проверка

1. На городском маршруте дождаться расчёта, записать сумму и оформить заказ. Сумма/диапазон в карточках клиента, водителя и диспетчера должны совпасть.
2. Белокаменка → Белоусовка и обратный маршрут: 3500 ₸ за легковой автомобиль.
3. Для направления без прайса при недоступном маршруте заказ не отправляется; видна ссылка для звонка диспетчеру.
4. При ставке 15% и цене 1040 ₸ комиссия — 156 ₸; при 0% — 0 ₸. Изменение ставки уже после принятия заказа не меняет комиссию этой поездки.

Автоматические проверки: `npm run check`, DOM-проверки в `tests/firestore`, финансовые проверки с локальным эмулятором Firestore. Для проверки не следует создавать реальные заказы пассажирам.

## v67: цена клиента и повышение во время поиска

- Для онлайн-такси (включая категории, межгород и предварительные поездки) и доставки рядом с обычным заказом доступна своя цена. Отдельный аукцион сохраняет прежний выбор водителя клиентом; обычный заказ по своей цене получает первый принявший водитель.
- Без фиксированного тарифа такси: `round(max(800, roadMeters / 1000 * 230) * largestMultiplier)`; далее действующая надбавка категории автомобиля. Фиксированные тарифы продолжают использовать существующую базу. Географическое сопоставление новой базы по координатам — отдельная доработка, этот выпуск её не реализует.
- Цена клиента является окончательной: повторных коэффициентов и округлений нет. Доставка сохраняет свой тариф; покупки не входят в комиссионную базу.
- `settings/customerPricing`: enabled, quickPercentages (до 5), minimumIncrease, maximumPrice, taxiMinimum, deliveryMinimum. Настройки доступны диспетчеру в разделе настроек. Последние два минимума относятся к резервному сценарию без автоматического расчёта.
- Заказы сохраняют `calculatedPrice`, `customerOfferPrice`, `finalDisplayedPrice`, `pricingType`, `calculationType`, `priceUpdatedAt`, `customerIncreasedPrice`, `priceRevision`, `routeDistanceMeters`. Для совместимости `priceAmount` остаётся расчётной базой комиссии и равен `finalDisplayedPrice`.
- Повышение выполняет транзакция: только автор, статус searching, водитель не назначен, сумма больше текущей. Исходный расчёт неизменен. Аудит `orders/{id}/priceChanges/{operationId}` создаётся атомарно. Повтор операции с тем же ID не меняет сумму повторно.
- Создание новых заказов использует сохранённый UID/UUID и транзакцию для заказа и контакта. При неизвестном результате показывается «Отправка не подтверждена» и проверка той же операции, а не новый заказ. Черновик удаляется после подтверждения сервера.
- Все активные привязанные водители читают свободные заказы независимо от населённого пункта, текущей занятости и баланса; ограничения категории/занятости/средств проверяются при принятии. Заблокированные и непривязанные аккаунты не читают заказы.
- Пуш повышения использует существующие подписки, проверяет актуальную ревизию/статус, подавляет повторы и ограничен одним уведомлением заказа в минуту. Отдельные повторные доставки FCM при сбое между отправкой и записью результата возможны; уведомления имеют один тег заказа. Обновление карточки не зависит от пуша.
- До установки новых правил браузер не включает предложение цены при недоступности публичных настроек. Обычная отправка остаётся совместимой со старыми правилами.

### Установка в существующий Firebase

Из авторизованного Cloud Shell, в свежей копии репозитория:

```bash
bash scripts/deploy-customer-pricing.sh
```

Скрипт устанавливает только `notifyDriversOfPriceIncrease` и правила Firestore проекта `taxiuspeh-76d55`. Индексы, данные и другие функции не удаляются. После сообщения Deploy complete обновите приложение. Публичные настройки отсутствующего документа используют безопасные значения по умолчанию; сохранение через диспетчерскую панель создаёт документ.

### Проверка

`npm run check`; `node compact-booking-ui.test.mjs` из tests/firestore; в эмуляторе — customer-pricing.test.mjs и driver-finance.test.mjs. Проверяются расчёт/предложение/резервный режим, старые заказы, запрет снижения, чужой аккаунт, повтор операции, гонки с принятием и индивидуальная комиссия. Live-проверка после установки: один обычный тестовый заказ, повышение во время поиска, принятие и отсутствие кнопки повышения после назначения.
