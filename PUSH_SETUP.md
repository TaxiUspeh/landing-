# Обновление пушей: версия 59

В версии 59 добавлены тестовый пуш на текущее устройство и уведомление при
назначении водителя на уже существующий заказ. Публикация сайта через GitHub Pages
не развёртывает серверные функции Firebase. Для этих возможностей нужен отдельный шаг ниже.

## Развёртывание в Firebase

Откройте [Google Cloud Shell](https://shell.cloud.google.com/?project=taxiuspeh-76d55)
под Google-аккаунтом, у которого есть доступ к проекту TaxiUspeh. Выполните:

```bash
push_workdir=$(mktemp -d -t taxi-push-v59-XXXXXX)
git clone --depth 1 --branch main https://github.com/TaxiUspeh/landing-.git "$push_workdir"
cd "$push_workdir"
npx --yes firebase-tools@14.16.0 login --no-localhost
bash scripts/deploy-driver-push.sh
```

Вход выполняется на странице Google; код авторизации вводится только в терминал
Cloud Shell. Дождитесь `Deploy complete!`. Затем в
[Firebase Functions](https://console.firebase.google.com/project/taxiuspeh-76d55/functions)
должны быть три функции в регионе `us-central1`:

- `notifyDriversOfNewOnlineOrder` — новые заказы клиентов и диспетчера;
- `notifyDriversOfOrderAssignment` — назначение существующего заказа водителю;
- `sendDriverTestPush` — тестовое уведомление на своё устройство.

Скрипт публикует только эти три функции. Правила Firestore, индексы, балансы и заказы
не изменяются. В проекте уже должен быть включён тариф Blaze для Cloud Functions.
Используйте Node.js 22 или новее в терминале; серверный runtime задан как Node.js 22.

## Проверка на телефоне

1. Откройте [кабинет водителя](https://taxiuspeh.github.io/landing-/drivers.html?v=59)
   на проверяемом телефоне, обновите страницу и перейдите в «Профиль».
2. Подключите уведомления. Нажмите «Отправить тестовый пуш».
3. Сверните кабинет и заблокируйте экран, сохранив вход в аккаунт.
   Сервер подождёт 10 секунд после начала обработки и отправит уведомление только
   на это устройство. Первый запуск функции может занять дополнительное время.
4. Повторный тест доступен через минуту. Тест не создаёт заказ и не списывает комиссию.
5. Если оставить кабинет открытым, он покажет «Тестовый пуш получен на это устройство»
   при получении сообщения FCM. «Проверить звук» — отдельная местная проверка.

Ответ «Тестовый пуш передан в Firebase» подтверждает принятие сообщения сервисом,
а появившееся уведомление на телефоне — его фактическое получение. Время доставки
может зависеть от сети и ограничений телефона.

Для проверки назначения используйте свою тестовую карточку: создайте заказ без
назначения, затем назначьте тестового водителя на этот существующий заказ. Ожидается
«Диспетчер назначил заказ». После проверки отмените тестовый заказ в диспетчерской.

## Если тест не сработал

- `functions/not-found`: функция ещё не развёрнута в нужном проекте/регионе.
- `functions/internal`, `functions/unavailable`, `functions/deadline-exceeded`:
  проверьте завершение развёртывания, сеть и журнал `sendDriverTestPush`.
  Один такой код сам по себе не доказывает отсутствие функции.
- `functions/failed-precondition`: переподключите уведомления на этом устройстве.
- `functions/permission-denied`: проверьте связь Google UID → driverAccounts → drivers.
- `functions/resource-exhausted`: подождите минуту перед следующим тестом.

## Технические сведения

Callable проверяет Firebase Auth, владельца выбранной подписки, активность аккаунта
и совпадение UID в карточке водителя. Привязка проверяется повторно после задержки.
Клиент не передаёт адресата, произвольный FCM-токен или текст рассылки.

Сервер использует закрытые для клиентской записи коллекции `driverPushTestLimits`
для ограничения частоты и `driverPushDeliveries` для повторов событий Firestore.
У записей доставки есть `expiresAt`; автоматическое удаление по нему требует
отдельной TTL-политики Firestore. Для работы пушей такая политика не обязательна.
Успешные токены сохраняются как хеши: при частичном сбое повторяются оставшиеся.
Атомарная гарантия «ровно один раз» между FCM и Firestore невозможна; одинаковый
notification tag уменьшает дубли на устройстве при редком сбое между отправкой и записью.

Функция назначения игнорирует обычное редактирование заказа, самостоятельное принятие,
отменённые/переназначенные заказы и события старше пяти минут. Маршрут, телефон и
имя клиента в пуш не включаются.

Документация: [вызов функций из приложения](https://firebase.google.com/docs/functions/callable),
[события Firestore и повторная доставка](https://firebase.google.com/docs/functions/firestore-events).
