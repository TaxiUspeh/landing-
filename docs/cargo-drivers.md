# Раздельные карточки водителей

Версия 69: один человек, один ID, один Google UID и общий баланс. Легковой автомобиль хранится в прежних полях drivers/{id}; грузовой — в cargoProfile этого же документа. Старые водители сохраняют легковое направление без миграции. У грузового водителя passengerEnabled=false. У направлений отдельные статусы и проценты комиссии; общий status блокирует человека целиком.

## Подключение

Из актуальной копии репозитория в Google Cloud Shell выполните `bash scripts/deploy-cargo-drivers.sh`. Скрипт обновит индекс запросов, функции уведомлений и правила доступа, затем включит карточки. Учетная запись Cloud Shell должна иметь доступ к проекту taxiuspeh-76d55. Повторный запуск безопасен. Карточки реальных водителей скрипт не создаёт и не изменяет.

После обновления правил водителям нужно обновить кабинет: старые версии запрашивали общий список заказов, теперь такой запрос запрещён. Публикация сайта обновляет кеш установленного приложения. Если индекс ещё строится, дождитесь статуса READY в Firebase → Firestore → Indexes.

## ID 30: добавить Газель

1. Диспетчер → Водители → раздел карточек «Грузоперевозки».
2. Укажите существующий ID 30 и нажмите «Добавить существующего водителя».
3. Проверьте имя и телефон в подтверждении. Новая карточка приостановлена.
4. Заполните модель, цвет, госномер, тип и размеры кузова, реальную грузоподъёмность. Укажите комиссию, переведите статус направления в «Принимать заказы», сохраните.

Для нового грузового водителя используйте форму «Добавить водителя», выберите направление «Грузоперевозки» и свободный ID. Он появится только в грузовом разделе. Вход привязывается тем же способом по Google UID.

Имя, телефон, UID, баланс и лимит долга общие — их изменение видно из обеих карточек. Автомобиль, статус направления и комиссия раздельные. Изменение грузовой карточки сохраняется в driverServiceHistory. Легковая финансовая история остаётся в driverFinanceHistory.

## Заказы и уведомления

Грузовые заказы, созданные диспетчером, видят и получают только водители с активной грузовой карточкой. Легковые заказы доступны легковому направлению. ID 30 с двумя активными карточками получает оба вида уведомлений. Фильтры «Все заказы / Легковые / Грузовые» меняют только список, не рассылку. Они также фильтруют историю поездок. Кнопка назначения выбирает соответствующий автомобиль.

Принятие любого заказа атомарно занимает один driverStates/{uid}. Второй заказ одновременно взять нельзя. В заказе фиксируются автомобиль и комиссия направления. Комиссия списывается с общего баланса один раз при завершении; дальнейшая правка карточки не меняет уже принятую поездку.

## Тариф и клиентский заказ

Этот выпуск разделяет карточки и распределение заказов. Клиентская форма грузоперевозки и её отправка через WhatsApp сохраняются. Диспетчер создаёт грузовой заказ и вводит согласованную общую стоимость. Существующие 6000 ₸/час не превращаются автоматически в итог поездки. Расчёт километража и прямой онлайн-заказ грузоперевозки требуют отдельного согласования тарифа.

## Проверка

`npm run check`; DOM-проверки в tests/firestore; Firebase Emulator Suite проверяет изоляцию чтения, запрет самостоятельной регистрации направления, подмену автомобиля и комиссии, одновременное принятие двух заказов, завершение грузовой поездки и единый баланс. Тесты не используют рабочую базу.
