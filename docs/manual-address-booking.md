# Ручной адрес и своя цена — v73

Такси, межгород, категории автомобилей, предзаказ и доставка принимают текстовый адрес без обязательного совпадения со справочником и без обязательного населённого пункта. Пустой адрес не принимается. Для точки без адреса показываются координаты; обратный поиск ограничен 2,5 секунды, после чего точка сохраняется без его результата.

«Предложить свою цену» доступно при заполненном маршруте, включая ожидание и ошибку расчёта. Сумма, введённая без готового расчёта, сохраняет приоритет при позднем ответе. При отправке расчёт повторно не запускается. Минимумы, максимальная сумма, целые тенге, телефон, пассажиры, дата предзаказа и список товаров продолжают проверяться. Обычный заказ по готовому тарифу не требует своей цены.

## Firebase

В авторизованном Cloud Shell из корня свежей копии репозитория:

```bash
bash scripts/deploy-manual-booking.sh
```

Скрипт публикует только `firestore.rules`, без изменения функций, водителей и заказов. Затем нужно обновить страницы клиента и водителя.

Новое необязательное поле `routeCoordinates` содержит список `{lat, lon}` либо `null`, строго в порядке подачи, остановок, назначения. Правила проверяют длину списка, допустимые координаты и отсутствие посторонних полей. Водитель открывает выбранные координаты в навигаторе; для старых заказов используются адреса.

Совместимость до публикации правил: клиент проверяет серверное чтение `settings/bookingCoordinates` (документ создавать не требуется). Старые правила запрещают чтение, поэтому новое поле пока не отправляется. Текст «Точка на карте: …» и своя цена продолжают сохраняться; навигатор распознаёт такую подпись. Это не отменяет обновление правил: отдельные числовые координаты включаются после него. Клиент не получает новых прав на изменение существующих заказов.

## Проверка

- `npm run check`: тарифы, сохранение пользовательской суммы реальными обработчиками, замедленная авторизация, неверные суммы, совместимость и навигация.
- `node tests/firestore/compact-booking-ui.test.mjs`: ручной адрес на казахском, отсутствие населённого пункта, зависший поиск точки, поздний расчёт, сохранение своей цены и валидация.
- Из `tests/firestore`: `firebase emulators:exec --config ../../firebase.test.json --only firestore --project demo-taxi-rules-check "node customer-pricing.test.mjs"` — создание заказа, координаты, права доступа, цена, принятие, комиссия и повторная отправка после потери ответа.

Заказы на рабочем проекте при проверке не создаются. Если связь с Firebase недоступна, приложение сохраняет попытку отправки и повторяет её с тем же идентификатором, чтобы не создать дубль.
